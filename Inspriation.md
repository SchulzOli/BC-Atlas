# Inspiration: D2 Diagram Improvements for BC Atlas

## Scope

This document records ideas inspired by Archify for improving BC Atlas diagrams while keeping D2 as the renderer. It is an inspiration matrix, not an implementation plan.

BC Atlas already has a strong base: focused architecture views, D2 source generation, bundled SVG rendering through `@terrastruct/d2`, Dagre/ELK selection, D2 themes, semantic edge styling, tooltips, source links, a legend, and an SVG preview in the Control Center (`src/d2.js`, `src/svg.js`, `src/views.js`, `src/docs/web/app.js`).

Archify is not D2-based, so the valuable parts to adapt are its reader experience, validation discipline, deterministic delivery, and evidence model—not its hand-positioned renderer.

Archify demonstrates typed inputs, deterministic validation, self-contained interactive HTML, and dark/light visual presets.[1][2]

It also demonstrates finite motion, search, route and reach exploration, guided views, canonical exports, architecture deltas, and atomic delivery receipts.[6][8]

**Dependency notation:** `None` means no package addition: use Node.js/browser APIs or dependencies already present in `package.json`. Optional dependencies are not required for the base feature.

## Improvement matrix

| Priority | Improvement | Current BC Atlas baseline / gap | D2-oriented adaptation | New npm dependencies | Other prerequisites | Verification / acceptance signal |
| --- | --- | --- | --- | --- | --- | --- |
| **P0** | **Self-contained interactive HTML output** | SVG is generated and shown in the Control Center, but a diagram is not yet a portable, standalone viewer. | Add `html` as an output format that embeds the generated D2 SVG, a compact toolbar, the resolved model as JSON, and local CSS/JS. Start with pan, zoom, reset, fit, and fullscreen. Keep `.d2` beside the HTML as the editable source. Archify treats one self-contained HTML file as its trusted shareable artifact.[1][6] | **None** — reuse `@terrastruct/d2`; use native DOM, Pointer Events, and `viewBox` transforms. | A modern browser. | Generated HTML opens offline; no network requests; mouse, touchpad, and keyboard navigation work; SVG and D2 outputs remain unchanged. |
| **P0** | **Stable semantic identity in rendered SVG** | The model has stable object keys, but the generated SVG is currently inserted as opaque D2 output. Reader features cannot reliably address nodes and edges. | After D2 rendering, annotate SVG elements with `data-node-key`, `data-edge-id`, `data-edge-from`, `data-edge-to`, source location, confidence, and relation kind. Keep the resolved model as the source of truth; fail closed when an SVG element cannot be mapped unambiguously. Archify uses stable semantic IDs for focus, deep links, routes, and deltas.[2][6] | `@xmldom/xmldom` for robust Node-side SVG parsing and serialization. | None. | Unchanged input produces unchanged semantic IDs; duplicate or missing mappings produce a diagnostic instead of a guessed link. |
| **P0** | **Theme parity and visual presets** | D2 supports `theme`, `darkTheme`, `sketch`, padding, and scale, but the CLI/configuration surface exposes only part of this, and the Control Center is light-only. | Expose light/dark theme pairs and a small bounded preset set such as `classic`, `blueprint`, and `presentation`. Presets may change D2 theme IDs, fonts, stroke widths, container treatment, and viewer CSS, but must not change topology. Archify keeps one semantic color vocabulary across themes and presets.[2][3] | **None** — reuse D2 compile options and CSS custom properties. | None. | Snapshot the same diagram in every preset/theme; node and edge counts and stable IDs are identical; WCAG contrast checks pass for text and controls. |
| **P0** | **Adaptive, configurable legend** | `renderD2()` emits one text legend based on used edge kinds; users can only show or hide it. | Add legend modes `auto`, `all`, and `hidden`, plus label overrides and per-entry visibility. Generate the legend from actual node/relation kinds and confidence overlays. If it cannot fit, emit a diagnostic rather than overlapping the graph. This follows Archify's typed legend contract.[2][7] | **None** — validate the configuration with existing `zod`. Do **not** add AJV. | None. | Unit tests cover unused kinds, custom labels, hidden entries, duplicate labels, and diagrams too small for the requested legend. |
| **P0** | **Canonical export menu** | CLI exports D2/SVG directly; PNG/PDF require the external D2 executable. The Control Center has no diagram export controls. | In standalone HTML and the Control Center, download the canonical SVG and rasterize it to PNG/JPEG/WebP through an isolated canvas clone. Strip focus, search, hover, camera, and temporary overlays before export. Archify explicitly separates canonical exports from viewer state.[1][6] | **None** for browser export. Optional `sharp` only if deterministic headless CLI raster export is required without the D2 executable. | Browser Canvas APIs; optional native binaries installed by `sharp`. | Export hashes are stable for the same browser/runtime; exported images contain the full diagram and no toolbar, selection, or temporary viewer state. |
| **P0** | **Post-render geometry quality gate** | D2 performs layout, but BC Atlas does not inspect the rendered SVG for clipped labels, edge-through-node defects, unreadably small text, or viewer/legend collisions. | Parse the rendered D2 SVG and add quality profiles such as `standard` and `showcase`. Check finite geometry, node overlap, edge-to-unrelated-node intersection, label bounds, minimum projected text size, legend clearance, and viewport containment. Return stable diagnostic codes, subjects, measurements, and supported fixes. Archify treats these checks as deterministic gates rather than visual-polish claims.[4][7][8] | `@xmldom/xmldom` (shared with semantic annotation) and `svg-path-properties` for path measurement. | None for static SVG checks. | Each rule has a focused failing fixture and a passing regression; diagnostics identify the exact node/edge and measured clearance. |
| **P0** | **Atomic diagram delivery with receipts** | Outputs are written directly. A render/check failure can leave partial or stale combinations of `.d2` and final output. | Render to same-directory candidate files, validate them, then atomically replace the target pair. Emit a JSON receipt with input/model/artifact SHA-256 hashes, byte counts, renderer options, node/edge counts, and validation status. Preserve the last trusted output on failure. Archify uses this distinction between a rendered candidate and a delivered artifact.[4][8] | **None** — use `node:fs`, `node:crypto`, and existing model metadata. | Filesystem support for same-volume rename. | Fault-injection tests prove that renderer, validator, and commit failures preserve the previous `.d2` and final artifact. |
| **P0** | **Automated browser visual checks** | Unit tests prove D2/SVG generation but do not verify the exact HTML/SVG at multiple viewports and themes. | Add a dev-only visual check that opens the delivered HTML, verifies containment/readability, captures light/dark screenshots, and records an artifact-bound JSON receipt. Keep automated evidence separate from human visual review, as Archify does.[8] | Dev dependency `playwright`. | Playwright Chromium download; CI cache for the browser binary. | CI checks at 1440×900, 1600×1000, 1920×1080, and 2048×1320; screenshots are tied to the artifact hash; missing Chromium reports `skipped`, not `passed`. |
| **P1** | **Node finder and semantic details panel** | D2 tooltips expose source and edge evidence, but discovery is hover-based and hard to use on large diagrams or with a keyboard. | Search labels, IDs, object types, namespaces, members, and source paths. Focusing a node opens one details panel with exact incoming/outgoing relations, diagnostics, source links, permissions, and data-access evidence. Archify centralizes this in Node Finder and a Semantic Passport.[3][6] | **None** — query the embedded resolved model. | Stable semantic identity from the P0 row above. | Search is case-insensitive and keyboard accessible; every displayed count equals the model; closing restores the prior viewport. |
| **P1** | **Upstream/downstream reach and exact route probe** | BC Atlas can generate focused object/call/workflow views, but readers cannot interactively trace the already-rendered graph. | Traverse only authored/resolved directed model edges. Highlight upstream or downstream reach from one node, or the shortest exact route between two nodes. State explicitly that graph reach is not runtime impact or a blast radius. Archify applies the same truth boundary.[1][6] | **None** — breadth-first traversal is small and can use native collections. | Stable node/edge IDs and embedded model JSON. | Route endpoints and each hop must exist in the model; stale/unreachable/conflicting routes fail closed; unrelated topology is only visually de-emphasized, never removed from canonical export. |
| **P1** | **Guided views and shareable deep links** | View selection occurs before rendering; a reader cannot save a focused state inside one artifact. | Allow up to a bounded number of named chapters containing stable node IDs and a note. Restore viewer state from URL fragments such as `#focus=`, `#route=`, and `#view=` without changing the D2 source. Archify derives guided stories and stable links from authored IDs.[2][6] | **None** — use `URLSearchParams`/fragment parsing and `history.replaceState`. | Stable semantic identity. | Invalid IDs are ignored with a visible status; copied links restore the same finite state after reload; canonical exports remain state-free. |
| **P1** | **Revision-verified source evidence** | Nodes can link to a URL template and source line, but the link is not verified against a repository revision. | Optionally record repository URL plus full commit SHA in the artifact receipt. Before embedding a source link, verify Git origin, revision, blob, path, and requested line range. Ordinary diagrams remain source-link compatible without enabling strict evidence mode. Archify uses opt-in revision-pinned evidence.[2][4] | **None** — use the existing Git CLI through `node:child_process` and `node:crypto`. | `git` executable and a local repository checkout when strict evidence mode is enabled. | Repository mismatch, missing commit, changed blob, and invalid line range fail with distinct diagnostics; no verification claim is made when the mode is off. |
| **P1** | **Finite path animation with reduced-motion support** | Generated diagrams are static. | Add an opt-in `trace` mode to standalone HTML that animates existing D2 edge paths in a finite, reader-started sequence. Static remains the default; `prefers-reduced-motion`, print, page hiding, and canonical export always show complete static meaning. This mirrors Archify's motion contract.[3][6] | **None** — CSS, `requestAnimationFrame`, and SVG path APIs. | A browser supporting SVG path measurement; graceful static fallback otherwise. | No animation attributes in static output; animation ends; reduced-motion mode never starts; export output is byte-identical whether the viewer was playing or still. |
| **P1** | **Architecture change review** | `git diff` can compare generated text, but readers do not get a semantic Before/Delta/After view. | Canonicalize resolved models by stable IDs and compare components, relations, groups, and evidence separately from presentation. Render three D2 diagrams or one layered HTML review and classify added, removed, changed, moved-group, and rerouted facts. Archify's architecture delta keeps semantic, geometry, topology, evidence, and presentation changes separate.[1] | **None** — implement canonical sorting/diffing with native JavaScript. | Stable model/relationship IDs; two input revisions or model snapshots. | Input order and formatting do not affect the semantic diff; missing IDs fail closed; the receipt count equals the enumerated changes. |
| **P1** | **Dedicated sequence and lifecycle D2 projections** | BC Atlas has `call` and `workflow` views, but no reader-specific sequence or lifecycle projection. | Add a sequence view for one selected AL interaction and a lifecycle view for processes with states/retries/terminal outcomes. Keep them as projections of existing analyzed facts, not inferred stories. Archify separates architecture, workflow, sequence, data-flow, and lifecycle because each answers a different question.[1][4] | **None** — generate D2 sequence/lifecycle-compatible source with the existing renderer. | Sufficient analyzed event/order/state evidence; otherwise emit an explicit unsupported/insufficient-evidence diagnostic. | Golden examples prove ordering, branches, retries, and empty-state behavior; JSON output exposes the same facts as D2. |
| **P1** | **Accessibility and localized viewer chrome** | D2 SVG is visual; the Control Center has basic form accessibility but the diagram itself has no consistent keyboard model or localized descriptions. | Add SVG `<title>`/`<desc>`, keyboard-operable semantic nodes, visible focus, non-color state cues, and a bounded viewer locale. Keep authored AL names untouched and localize only renderer-owned UI. Archify applies this separation and rejects unsupported locale values rather than guessing.[2][3] | **None** — start with checked-in string dictionaries and native ARIA. | Human review with keyboard and a screen reader. | Automated axe-style assertions can be written without a package initially; manual NVDA/VoiceOver checklist records keyboard order, labels, focus visibility, and theme parity. |
| **P2** | **Last-good live preview** | Watch mode regenerates diagrams, while the Control Center requests renders manually; neither explicitly preserves the last verified artifact through half-written or invalid changes. | Watch one model/source digest, render privately, advance the browser only after all selected gates pass, and leave the prior verified diagram visible on failure. Archify treats this as an explicit desktop authoring mode, not a default service.[8] | **None** — reuse current watch/server infrastructure and Node file watching. | Loopback port for preview mode. | Half-written, deleted, duplicate, and superseded inputs do not replace/reload the last good artifact; identical bytes do not rebuild. |
| **P2** | **README/share-card exports** | Diagram exports optimize for full technical detail, not repository previews. | Add an explicit 1200×630 share-card variant that retains the complete diagram as quiet context and clearly labels any focused route/reach state. Keep it separate from canonical architecture evidence. Archify uses this distinction for communication assets.[1][6] | **None** in the browser; optional `sharp` for deterministic CLI generation. | Browser Canvas or `sharp` native binaries. | Exact 1200×630 dimensions; title and selected state fit; receipt marks the artifact as a communication variant, not validated topology. |
| **P2** | **Bundled semantic/brand marks** | Nodes are differentiated by color and labels only. | Add small generated SVG marks for AL object categories first. Optionally support a bounded, vendored brand catalog for external systems; marks must not replace type labels or recolor semantic categories. Archify treats marks as authored identity inside a stable semantic palette.[2][3] | Optional dev dependency `simple-icons`; generated icon data is committed so runtime adds no package. | License/attribution review for each external mark. | Unknown marks fail validation; generated catalog freshness is tested; diagrams remain understandable when marks are hidden. |

## Recommended first delivery slice

Implement the smallest coherent foundation before advanced interaction:

1. Self-contained HTML output.
2. Stable SVG semantic identity.
3. Adaptive legend and light/dark preset parity.
4. Canonical SVG/PNG export with viewer state removed.
5. Post-render quality diagnostics and atomic delivery receipts.
6. Browser checks for the exact delivered artifact.

This slice improves every existing D2 view without changing AL analysis semantics. Search, reachability, guided views, deltas, and animation then build on stable IDs and a verified HTML shell rather than each creating its own integration path.

## Explicit dependency summary

| Dependency | Classification | Needed for | Why it is new |
| --- | --- | --- | --- |
| `@xmldom/xmldom` | Runtime dependency | Semantic SVG annotation and static SVG quality checks | BC Atlas currently treats the rendered SVG as text; robust annotation needs a Node-side XML DOM. |
| `svg-path-properties` | Runtime dependency | Edge length, bounds, sampling, and edge-to-node/label clearance checks | D2 emits SVG paths; Node has no native SVG geometry API. |
| `playwright` | Dev dependency | Multi-viewport, light/dark visual evidence for delivered HTML | The current test suite does not launch a browser. |
| `sharp` | Optional runtime dependency | Deterministic CLI-side PNG/JPEG/WebP and share-card output without external D2 | Browser exports and existing D2 CLI rendering remain valid without it. |
| `simple-icons` | Optional dev dependency | Generating a bounded external brand-mark catalog | Generated SVG data can be committed, so no runtime icon package is needed. |
| Playwright Chromium | External/dev prerequisite | Browser visual checks | Installed and cached by Playwright; not shipped in the BC Atlas npm package. |
| `git` executable | Conditional external prerequisite | Strict revision-verified source evidence | Already common in repository workflows; required only when evidence verification is enabled. |

Archify itself keeps these capabilities out of production npm dependencies and uses development-time packages for schema compilation, document checks, and icon generation.[5] The BC Atlas recommendations above follow the same principle where practical, while reusing its existing runtime stack.

No new dependency is recommended for pan/zoom, themes, legends, route/reach traversal, deep links, finite animation, atomic writes, hashing, lifecycle/sequence projection, i18n dictionaries, or last-good preview. Reuse native browser/Node.js APIs and the existing `@terrastruct/d2`, `zod`, and `dompurify` dependencies.

## Deliberate non-goals

- Do not replace D2 with Archify or copy Archify's hand-positioned renderer.
- Do not add a hosted sharing service, telemetry, WYSIWYG editor, or a second graph database.
- Do not call static graph reachability “impact,” “blast radius,” or runtime causality.
- Do not let viewer state alter canonical D2, SVG, or model facts.
- Do not claim automated geometry or screenshot checks are human visual review.
- Do not add AJV solely to mirror Archify; BC Atlas already has `zod` and should extend its existing validation approach.
