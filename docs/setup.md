# Guided setup

`bca setup` decides once what BC Atlas should do in a repository:

- **Features:** health check, architecture report, user guides or test cases, object catalog.
- **Triggers:** Git hooks (Husky or plain Git), pull requests, and a schedule (cron).
- **Sync:** what happens with generated files. Each trigger can verify, stage,
  publish, commit, or open a pull request.

Everything ends up in `.bca.json`, Git hook files, and one pipeline file. All
of them call [`bca run`](./automation-and-ci.md), so local hooks and pipelines
behave the same way.

You choose how to answer the questions:

| Way | Command | For |
| --- | --- | --- |
| Terminal wizard | `bca setup` | Answering the questions yourself |
| Recommendations | `bca setup --yes` | Taking the detected defaults |
| Your AI agent | `bca setup agent --agent claude` then `/bca-setup` | A guided conversation that explains the options |
| Scripts | `bca setup plan` + `bca setup apply ...` | CI templates and repeatable setups |

The agent is optional. It never edits files itself; it asks the questions and
calls `bca setup apply`.

## What setup detects

```sh
bca setup plan ./app
```

```text
BC Atlas setup for BC Atlas Warehouse Example 1.0.0.0

  Git                yes (github)
  UI tests           2 documented scenario(s) in .
  Translations       de-DE
  Existing setup     none

Recommended answers
  --features         check, report, docs
  --tests            .
  --hooks            husky
  --pre-commit       check
  --pre-push         report, docs
  --hook-sync        verify
  --ci               github
  --ci-sync          verify
  --schedule         0 6 * * 1
  --schedule-sync    pull-request
  ...
```

`--format json` returns the same data for tools: detected `facts`, every
question with its `flag`, `options`, `recommended` value, and `when`
condition, and a ready `apply` command.

## Questions

| Topic | Flag | Choices |
| --- | --- | --- |
| Features | `--features` | `check`, `report`, `docs`, `codegraph` |
| UI tests | `--tests` | Folder with documented AL UI tests (for `docs`) |
| Doc formats | `--docs-export` | `markdown`, `html`, `dita`, `ado-csv` |
| Doc type | `--docs-as` | `guide`, `testcase` |
| Language | `--language` | e.g. `en-US`, `de-DE` (captions from the app's XLIFF) |
| Git hooks | `--hooks` | `husky`, `git`, `none` |
| Before commit | `--pre-commit` | features, or `none`; keep it fast |
| Before push | `--pre-push` | features, or `none` |
| Hook sync | `--hook-sync` | `verify`, `stage`, `none` |
| Pipeline | `--ci` | `github`, `azure-devops`, `none` |
| Pipeline sync | `--ci-sync` | `verify`, `artifact`, `none` |
| Schedule | `--schedule` | cron expression in UTC, or `none` |
| Schedule sync | `--schedule-sync` | `pull-request` (GitHub), `commit`, `artifact`, `verify`, `none` |

Omitted answers use the recommendation. Lists are comma-separated, and `none`
means an empty list.

## Apply

```sh
bca setup apply ./app --features check,report,docs --tests test \
  --hooks husky --pre-commit check --pre-push report,docs --hook-sync verify \
  --ci github --ci-sync verify --schedule "0 6 * * 1" --schedule-sync pull-request \
  --dry-run
```

`--dry-run` lists what would be created or updated. Without it, setup writes:

| File | When |
| --- | --- |
| `<app>/.bca.json` | Always. Existing settings are kept and the `automation` and `docs` sections are updated. |
| `.husky/pre-commit`, `.husky/pre-push` | `--hooks husky`. Existing hook commands are kept, and the BC Atlas line is added or replaced. |
| `package.json` | `--hooks husky`. Adds `husky` and `bc-atlas` as dev dependencies and `"prepare": "husky"`. |
| `.githooks/pre-commit`, `.githooks/pre-push` | `--hooks git`. Setup also runs `git config core.hooksPath .githooks`. |
| `.github/workflows/bc-atlas.yml` | `--ci github` |
| `azure-pipelines.bc-atlas.yml` | `--ci azure-devops` |

Pipeline files that were not generated by `bca setup` are never overwritten
unless you pass `--force`. Running `apply` again with the same answers changes
nothing. The result ends with the next steps, for example `npm install` for
Husky and a first `bca run`.

## Let your agent guide the setup

```sh
bca setup agent --agent claude    # .claude/commands/bca-setup.md   -> /bca-setup in Claude Code
bca setup agent --agent copilot   # .github/prompts/bca-setup.prompt.md -> /bca-setup in VS Code Copilot Chat
bca setup agent --agent cursor    # .cursor/commands/bca-setup.md   -> /bca-setup in Cursor
bca setup agent                   # prints the prompt for any other agent
```

The command file tells the agent to:

1. Run `bca setup plan --format json` and summarize what it found.
2. Ask the questions topic by topic, offering the recommendations.
3. Preview the answers with `bca setup apply ... --dry-run --format json`.
4. Apply after your confirmation and follow the next steps.

Agents connected through MCP can use the same flow with the
`bc_atlas_setup_plan`, `bc_atlas_setup_apply` (dry run by default), and
`bc_atlas_run` tools; see [Agent integration](./agent-integration.md).

To change the setup later, run `bca setup` or `/bca-setup` again. The plan
starts from your current `.bca.json`.
